#+title: go-template-mode
#+options: toc:t

=go-template-mode= is an Emacs major mode for files written primarily in Go
=text/template= syntax.  It highlights complete template actions while leaving
the surrounding output as plain text.

#+begin_src text
  {{- if .Enabled }}
  Hello, {{printf "%s" .Name}}
  {{- end }}
#+end_src

Version 2.0.0 is recommended for new and existing users.  It provides
action-scoped highlighting, current Go template vocabulary, incremental Font
Lock integration, and a reusable fontification API.

* Choose the right mode

| Buffer contents                    | Recommended setup                              |
|------------------------------------+------------------------------------------------|
| Primarily Go template or plain text | =go-template-mode=                            |
| HTML containing template actions   | =html-mode= with =go-template-helper-mode=    |
| Helm or YAML templates             | A YAML mode with =go-template-helper-mode=    |

The companion
[[https://codeberg.org/rch/go-template-helper-mode][go-template-helper-mode]]
adds the same template highlighting to another major mode without replacing
that mode's indentation, comments, keymap, or host-language faces.

* Features

- Highlights delimiters and whitespace-trim markers.
- Highlights variables, fields, action words, constants, strings, character
  constants, and standard predefined functions.
- Highlights ordinary and trim-marked multiline template comments.
- Restricts template faces to complete ={{ ... }}= actions.
- Ignores delimiter-looking text inside template strings.
- Uses JIT Lock for incremental, demand-driven fontification.

* Requirements

- Emacs 28.1 or later.
- No external runtime dependencies.

* Upgrading from 1.x

Version 2.0.0 changes fontification behavior:

- Ordinary output text that resembles a template keyword or function is no
  longer highlighted.
- Package-specific HTML tag highlighting was removed.  Use =html-mode= with
  =go-template-helper-mode= for embedded HTML.
- Manual installations must include both =go-template-mode.el= and
  =go-template-mode-font-lock.el=.
- Existing helper users should upgrade =go-template-mode= first, then upgrade
  =go-template-helper-mode= to version 2.0.0.

See [[file:NEWS][NEWS]] for the complete user-visible changes.

* Installation

** MELPA

Install =go-template-mode= from MELPA or MELPA Stable.  The package supplies
autoloaded associations for =.gotmpl=, =.tpl=, and =.tmpl=, so no additional
configuration is required.

At the time of this README update, both archives still exposed the previous
implementation while publication of 2.0.0 was pending.  Check that the archive
entry has refreshed before installing.  Until then, use the manual installation
instructions with the
[[https://codeberg.org/rch/go-template-mode/src/tag/2.0.0][2.0.0 source tree]].

With =use-package=:

#+begin_src elisp
  (use-package go-template-mode
    :ensure t)
#+end_src

** Manual

Place =go-template-mode.el= and =go-template-mode-font-lock.el= in the same
directory on =load-path=:

#+begin_src elisp
  (add-to-list 'load-path "/path/to/go-template-mode")
  (require 'go-template-mode)
#+end_src

* Usage

Open a =.gotmpl=, =.tpl=, or =.tmpl= file to activate the mode.  Use =M-;= to
insert or edit Go template comments with ={{/* ... */}}= delimiters.

** File association overrides

The generic =.tpl= and =.tmpl= extensions do not identify their surrounding
format.  Since =auto-mode-alist= uses its first matching entry, add a host-mode
association after package activation when that host should take precedence:

#+begin_src elisp
  (add-to-list 'auto-mode-alist '("\\.tpl\\'" . yaml-mode))
#+end_src

* Shared fontification API

Integrations can load the action-aware Font Lock layer without activating the
major mode:

#+begin_src elisp
  (require 'go-template-mode-font-lock)
  (go-template-mode-font-lock-install)
  ;; Later, in the same buffer:
  (go-template-mode-font-lock-uninstall)
#+end_src

Both functions are idempotent and affect only the current buffer.  When Font
Lock is active, uninstalling refontifies the buffer to restore host-language
faces.  Loading this library alone does not register file extensions or enable
=go-template-mode=.

* Large files

JIT Lock normally fontifies visible regions on demand rather than processing an
entire buffer when it opens.  The scanner uses search-based lexical operations
and does not maintain parser caches or background workers.

Optional idle-time fontification remains an Emacs user preference:

#+begin_src elisp
  (setq jit-lock-stealth-time 1
        jit-lock-stealth-nice 0.5)
#+end_src

Jumping directly into an unfontified, extremely action-dense multi-megabyte
buffer can still pause while Emacs establishes lexical context.

* Limitations

- Only the default ={{= and =}}= delimiters are supported.
- The mode intentionally provides no indentation engine.
- Unterminated actions, strings, comments, and actions with unbalanced
  parentheses are left unfontified; this is not a full template validator.
- Nested comments are not supported by Go templates.
- Application-defined functions are not recognized as predefined functions.
- HTML, YAML, and other surrounding languages require their own host mode.

* Development

Compile from source and run the ERT suite:

#+begin_src sh
  make clean all
#+end_src

Remove generated byte-code files:

#+begin_src sh
  make clean
#+end_src

** Manual font-lock check

The committed
[[file:tests/font-lock-manual.gotmpl][manual visual regression fixture]]
contains representative actions, host-language examples, and intentionally
malformed input.  It is for visual inspection, not template execution.

Open it with the major mode in an isolated Emacs:

#+begin_src sh
  emacs -Q -L . -l go-template-mode.el tests/font-lock-manual.gotmpl
#+end_src

Inspect the shared layer over built-in =html-mode=:

#+begin_src sh
  emacs -Q -L . -l go-template-mode-font-lock.el \
    --eval '(progn
      (find-file "tests/font-lock-manual.gotmpl")
      (html-mode)
      (go-template-mode-font-lock-install))'
#+end_src
