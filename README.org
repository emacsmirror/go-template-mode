#+title: go-template-mode
#+options: toc:t

A lightweight Emacs major mode for editing Go text/template (Go
templates).

It highlights complete template actions without parsing the surrounding
output format.  It uses Font Lock's incremental refontification and avoids
persistent parser caches or external dependencies.

* Features

- Highlights template delimiters and whitespace-trim markers
- Highlights variables, fields, action words, constants, and the standard
  predefined functions
- Highlights interpreted strings, raw strings, and character constants
- Highlights ordinary and trim-marked multiline comments
- Restricts template highlighting to complete ={{ ... }}= actions
- Handles delimiter-looking text inside template strings

* Requirements

- Emacs 28.1+

* Installation

** From MELPA

After installing from MELPA, enable it in your init:

#+begin_src elisp
  (use-package go-template-mode
    :ensure t
    :mode (("\\.gotmpl\\'" . go-template-mode)
           ("\\.tpl\\'" . go-template-mode)
           ("\\.tmpl\\'" . go-template-mode)))
#+end_src

** Manual

1. Put =go-template-mode-font-lock.el= and =go-template-mode.el= in the
   same directory on your =load-path=.
2. Add to your init file:

#+begin_src elisp
  (require 'go-template-mode)
#+end_src

File associations for =.gotmpl=, =.tpl=, and =.tmpl= are provided by the mode.

** With use-package (local checkout)

#+begin_src elisp
  (use-package go-template-mode
    :load-path "/path/to/repo/"
    :mode ("\\.\\(gotmpl\\|tpl\\|tmpl\\)\\'" . go-template-mode))
#+end_src

* Usage

- Open a =.gotmpl=, =.tpl=, or =.tmpl= file to activate the mode.
- =M-;= uses Go template comment delimiters for convenience: ={{/* ... */}}=

* Helm charts and embedded templates

Go templates can be embedded in HTML, YAML, and other formats.  In those
buffers, keep the format's major mode and add template highlighting with
the companion minor mode:

- =go-template-helper-mode=: adds Go template highlighting on top of
  another major mode without replacing its indentation or comment
  behavior.

In short:
- Use =go-template-mode= when the buffer is primarily template syntax or
  plain output text.
- Use =html-mode= plus =go-template-helper-mode= for HTML templates.
- Use a YAML major mode plus =go-template-helper-mode= for Helm templates.

The generic =.tpl= and =.tmpl= extensions do not identify the surrounding
format.  Override their file association when a host major mode should take
precedence.

* Shared fontification

The action-aware fontification layer is available separately for minor
modes and other integrations:

#+begin_src elisp
  (require 'go-template-mode-font-lock)
  (go-template-mode-font-lock-install)
  ;; Later, in the same buffer:
  (go-template-mode-font-lock-uninstall)
#+end_src

Both functions are idempotent and operate only on the current buffer.  When
Font Lock is active, uninstalling refontifies the buffer to restore host faces.
Loading the shared library does not register file extensions or activate
=go-template-mode=.

* Large files

Emacs normally uses JIT Lock to fontify visible regions on demand instead of
fontifying the entire buffer when it opens.  This applies to both the major mode
and integrations using the shared fontification library.

Users who want Emacs to fontify unseen regions while idle can enable JIT Lock's
optional stealth processing in their init file:

#+begin_src elisp
  (setq jit-lock-stealth-time 1
        jit-lock-stealth-nice 0.5)
#+end_src

Stealth processing is cooperative idle work, not a background thread, and is
therefore left as a user preference.  Jumping directly into an unfontified,
extremely action-dense multi-megabyte buffer can still pause while the mode
establishes lexical context.

* Development

Compile the package and run its ERT suite:

#+begin_src sh
  make all
#+end_src

Run only the tests or remove generated byte-code files:

#+begin_src sh
  make test
  make clean
#+end_src

** Manual font-lock check

The committed
[[file:tests/font-lock-manual.gotmpl][manual visual regression fixture]]
contains representative actions, host-language examples, and intentionally
malformed input.  It is for visual inspection from a repository checkout, not
template execution.

Open it in an isolated Emacs using the major mode:

#+begin_src sh
  emacs -Q -L . -l go-template-mode.el tests/font-lock-manual.gotmpl
#+end_src

To inspect the shared fontification layer over built-in =html-mode=:

#+begin_src sh
  emacs -Q -L . -l go-template-mode-font-lock.el \
    --eval '(progn
      (find-file "tests/font-lock-manual.gotmpl")
      (html-mode)
      (go-template-mode-font-lock-install))'
#+end_src

* Limitations

- No indentation engine (intentionally)
- Only the default ={{= and =}}= delimiters are supported
- Unterminated actions, strings, and comments and actions with unbalanced
  parentheses are left unfontified; this mode is not a full syntax validator
- Nested comments are not supported by Go templates
- Application-defined template functions are not recognized as predefined
  functions
- Surrounding HTML, YAML, and other languages require their own host mode
